7.1 Namespace

What is a namespace?

Simple meaning: A namespace is a named box that holds functions, variables, and classes. It stops two things from having the same name and fighting.

Think of a school:

  • Two students can both be named Ram.
  • We tell them apart by class: Class10::Ram and Class12::Ram.
  • A namespace is like the class name in front of Ram.

In code, std is a famous namespace. That is why we write std::cout.

7.1 Theory

Why does C++ need namespaces?

The problem

Your program and a library may both have a function called print or add. The compiler then says: “this name is already used.”

The fix

Put each group of names in its own box. Then you must say which box with ::.

  • A namespace is not a class. You do not create objects of a namespace.
  • You can open the same namespace again later and add more names (it is like adding more things to the same box).
  • std is the Standard Library box: cout, cin, string, endl live there.
7.1 Complete program

Two boxes, same function name — no clash

#include <iostream>
using namespace std;

namespace MathA {
    int add(int a, int b) {
        return a + b;
    }
}

namespace MathB {
    int add(int a, int b) {
        return a + 10;
    }
}

int main() {
    cout << "MathA::add(2, 3) = " << MathA::add(2, 3) << endl;
    cout << "MathB::add(2, 3) = " << MathB::add(2, 3) << endl;
    return 0;
}
MathA::add(2, 3) = 5
MathB::add(2, 3) = 13

Without namespaces, two functions both named add would be an error.

7.1 Creation

How to create a namespace

Remember: write namespace Name { ... }. Everything inside the braces belongs to that name.
#include <iostream>
using namespace std;

namespace MyMath {
    int add(int a, int b) {
        return a + b;
    }
    int square(int n) {
        return n * n;
    }
}

int main() {
    cout << "5 + 7 = " << MyMath::add(5, 7) << endl;
    cout << "4 squared = " << MyMath::square(4) << endl;
    return 0;
}
5 + 7 = 12
4 squared = 16
7.1 Usage · theory

Three ways to use a namespace

WayCodeWhen to use
:: (safest) MyMath::add(2, 3); You clearly show where the name comes from
using one name using MyMath::add; You need only one function often
using namespace using namespace MyMath; Short programs / exams — but can hide name clashes
Tip: Beginners often write using namespace std; at the top. It is OK for small lab programs. In big software, prefer std::cout.
7.1 Complete program

All three ways in one program

#include <iostream>
using namespace std;

namespace MyMath {
    int add(int a, int b) { return a + b; }
    int square(int n) { return n * n; }
}

int main() {
    // Way 1: ::  (always clear)
    cout << "Way 1  add    = " << MyMath::add(2, 3) << endl;

    // Way 2: bring only one name into this function
    using MyMath::add;
    cout << "Way 2  add    = " << add(10, 20) << endl;

    // Way 3: bring the whole namespace
    using namespace MyMath;
    cout << "Way 3  square = " << square(6) << endl;
    return 0;
}
Way 1 add = 5
Way 2 add = 30
Way 3 square = 36
7.1 Theory

Nested namespace and alias

Nested namespace

A box inside a box. College can contain Exam. You write College::Exam::passMark.

Namespace alias

A short nickname: namespace CE = College::Exam; then use CE::passMark.

  • Nesting keeps related names together (College → Exam → Hostel).
  • An alias is only a shorter name. It does not create a new box.
  • Exam question: “What does :: mean?” — scope resolution: “look inside this namespace.”
7.1 Complete program

Nested namespace + alias

#include <iostream>
using namespace std;

namespace College {
    namespace Exam {
        int passMark = 40;
        bool isPass(int m) {
            return m >= passMark;
        }
    }
}

int main() {
    namespace CE = College::Exam;   // alias = short name
    cout << "Pass mark = " << College::Exam::passMark << endl;
    cout << "55 pass?  " << CE::isPass(55) << endl;
    cout << "30 pass?  " << CE::isPass(30) << endl;
    return 0;
}
Pass mark = 40
55 pass? 1
30 pass? 0

1 means true, 0 means false.

7.2 Concept of Template

What is a template?

Simple meaning: A template is a mould (like a cookie cutter). You write the shape once. The compiler fills it with int, float, char, … when you need it.

Without a template you copy-paste the same logic three times. Only the type changes. A template says: “the type is a blank. Fill it later.”

1

Write the logic once

2

Call it with int, float, …

3

Compiler makes the real functions

7.2 Theory

Template vs overloading vs copy-paste

StyleWhat you writeBeginner view
Copy-paste biggerInt, biggerFloat, … Works, but easy to forget one copy
Function overloading Same name, different types, several functions Still many functions to maintain
Template One function, type is a blank T Best when the logic is identical

Two kinds you must know

  • Function template — a function that works for many types
  • Class template — a class that can store many types

vector<int> in C++ is a class template. The box is “vector”; the item type is “int”.

7.3 Function Template

Complete program: function template

Line to remember: template <typename T> means “T is a placeholder for a type.” You may also write template <class T> — same meaning for beginners.
#include <iostream>
using namespace std;

template <typename T>
T getMax(T a, T b) {
    if (a > b) return a;
    else return b;
}

int main() {
    cout << "max int    = " << getMax(10, 20) << endl;
    cout << "max double = " << getMax(2.5, 1.8) << endl;
    cout << "max char   = " << getMax('A', 'Z') << endl;
    return 0;
}
max int = 20
max double = 2.5
max char = Z
7.3 Theory

How the compiler fills in T

  • getMax(10, 20) → T becomes int
  • getMax(2.5, 1.8) → T becomes double
  • getMax('A', 'Z') → T becomes char

You do not write three functions. The compiler secretly makes them for you.

Beginner rule: both arguments should be the same type. getMax(10, 2.5) can confuse the compiler. Use an explicit type: getMax<double>(10, 2.5).
7.3 Complete program

Explicit type: getMax<double>

#include <iostream>
using namespace std;

template <typename T>
T getMax(T a, T b) {
    if (a > b) return a;
    else return b;
}

int main() {
    // 10 is int, 2.5 is double — tell the compiler: use double
    cout << getMax<double>(10, 2.5) << endl;
    cout << getMax<int>(10, 3) << endl;
    return 0;
}
10
10

Angle brackets after the name force the type. Useful in exams when mixed types appear.

7.4 Class Template

Complete program: a typed box

Simple meaning: A class template is a class where the data type is a blank. You must say the type in angle brackets: Box<int>.
#include <iostream>
#include <string>
using namespace std;

template <typename T>
class Box {
    T value;
public:
    void set(T v) { value = v; }
    T get() { return value; }
};

int main() {
    Box<int> marks;
    marks.set(85);
    Box<string> city;
    city.set("Kathmandu");
    cout << marks.get() << endl;
    cout << city.get() << endl;
    return 0;
}
85
Kathmandu
7.4 Theory

Class template vs function template

Function templateClass template
What it is One function, many types One class, many types
How you use it add(10, 20) — type often guessed Box<int> m; — type is required
Stores data? Usually no (just computes) Yes — members use T
Exam line template <typename T> above the function Same line above the class
Common mistake: writing Box marks;. It must be Box<int> marks;. Box<int> and Box<string> are like two different classes from one mould.

Save as 03_class_template.cpp

float mul = 10
7.5 Basics

What is exception handling?

Simple meaning: An exception is a problem that happens while the program is running (not while compiling). Exception handling means: “if something goes wrong, do not crash — catch it and show a clear message.”

Compile-time error

Forgot a semicolon. The program will not even start.

Runtime exception

User types 0 for divisor. Program is running, then boom — unless we catch it.

Examples: divide by zero, array index out of range, file not found, negative age.

7.5 Theory

Three kinds of problems (do not mix them)

KindWhenExampleFix with try/catch?
Syntax / compile error Before the program runs Missing ; No — the compiler stops you
Logic error Program runs, answer is wrong Used + instead of * No — you must fix the formula
Exception (runtime) Program runs, then a bad event Divide by 0, bad index Yes — throw and catch

Exception handling does not replace if. You still check the problem; throw is how you jump to the error handler.

7.5 Why bother?

Without handling vs with handling

Without

Program stops suddenly. User sees a crash or garbage.

With try / catch

Program prints: “Cannot divide by zero” and can continue or exit politely.

You separate normal work from “what if it fails?” That keeps main easy to read.

  • try = do the normal job
  • throw = “this went wrong, here is the error value”
  • catch = “I know this kind of error, I will handle it”
7.6 Mechanism

Three keywords: try, throw, catch

try

Put the risky code here. “Try this.”

throw

When a problem is found, throw a value (the error).

catch

Stand ready to catch that value and handle it.

Picture: You throw a ball (the error). Someone must catch it. If nobody catches it, the program ends.

The type you throw must match a catch: throw int → catch int. Throw a class → catch that class.

7.6 Theory

What happens, step by step

1

Enter try

2

If OK, finish try, skip all catch

3

If bad, throw — rest of try is skipped

4

Matching catch runs, then program continues after catch

  • Code after throw inside the same try never runs.
  • After a catch finishes, execution continues after the last catch (not back into the try).
  • C++ tries catch blocks from top to bottom and uses the first match.
7.6 Complete program

Divide by zero (throw an int)

#include <iostream>
using namespace std;

int main() {
    int a = 10, b = 0;
    try {
        if (b == 0)
            throw b;
        cout << "Answer = " << a / b << endl;
    }
    catch (int x) {
        cout << "Cannot divide by " << x << endl;
    }
    cout << "Program did not crash." << endl;
    return 0;
}
Cannot divide by 0
Program did not crash.

We threw an int, so we caught an int. The last cout still runs.

7.7 Example · int

Throw an error code (int)

#include <iostream>
using namespace std;

int main() {
    int page = 404;
    try {
        if (page == 404)
            throw page;
        cout << "Page found" << endl;
    }
    catch (int code) {
        cout << "Error code: " << code << endl;
    }
    return 0;
}
Error code: 404

Throwing an int is the simplest “basic type” exception. Common in lab questions.

7.7 Example · double

Throw a double (invalid temperature)

#include <iostream>
using namespace std;

int main() {
    double temp = -300.5;
    try {
        if (temp < -273.15)
            throw temp;
        cout << "Temperature is OK" << endl;
    }
    catch (double t) {
        cout << "Impossible temperature: " << t << endl;
    }
    return 0;
}
Impossible temperature: -300.5

Use double (or float) when the error value itself is a real number.

7.7 Example · char

Throw a char (invalid grade)

#include <iostream>
using namespace std;

int main() {
    char grade = 'X';
    try {
        if (grade != 'A' && grade != 'B' && grade != 'C')
            throw grade;
        cout << "Grade accepted" << endl;
    }
    catch (char g) {
        cout << "Invalid grade: " << g << endl;
    }
    return 0;
}
Invalid grade: X

A char exception is useful when the bad input is a single letter.

7.7 Example · string

Throw a string (file not found)

#include <iostream>
#include <string>
using namespace std;

int main() {
    string fileName = "marks.txt";
    bool fileExists = false;
    try {
        if (!fileExists)
            throw string("Cannot open ") + fileName;
        cout << "File opened" << endl;
    }
    catch (string msg) {
        cout << msg << endl;
    }
    return 0;
}
Cannot open marks.txt

Need #include <string>. Catch string, not int.

7.7 Example · C-string

Throw a C-string (const char*)

#include <iostream>
using namespace std;

int main() {
    const char* name = "";
    try {
        if (name[0] == '\0')
            throw "Name cannot be empty";
        cout << "Hello " << name << endl;
    }
    catch (const char* msg) {
        cout << msg << endl;
    }
    return 0;
}
Name cannot be empty
Do not mix: throw "hello" is const char*. throw string("hello") is string. They need different catch blocks.
7.7 Complete program

Many catch blocks — first match wins

#include <iostream>
#include <string>
using namespace std;

int main() {
    int kind = 2;   // try 1, 2, or 3
    try {
        if (kind == 1) throw 404;
        if (kind == 2) throw 3.14;
        if (kind == 3) throw string("No file");
        cout << "No error" << endl;
    }
    catch (int code) {
        cout << "int error: " << code << endl;
    }
    catch (double d) {
        cout << "double error: " << d << endl;
    }
    catch (string msg) {
        cout << "string error: " << msg << endl;
    }
    return 0;
}
double error: 3.14

Change kind to 1 or 3 to see the other catch blocks. Only one catch runs.

7.7 Catch all

Safety net: catch (...)

#include <iostream>
using namespace std;

int main() {
    try {
        throw 'X';
    }
    catch (int n) {
        cout << "Caught int: " << n << endl;
    }
    catch (...) {
        cout << "Some other error" << endl;
    }
    return 0;
}
Some other error
Put catch (...) last. If it is first, it swallows every error and the other catch blocks never run. Three dots mean “any type”.
7.7 Theory

Catch order rules (exam favourite)

  • Write specific types first: int, string, your class.
  • Write parent types later: if you catch exception&, put it after specific ones like invalid_argument.
  • Write catch (...) last as a safety net.
  • A thrown value is matched by type, not by the message text.
  • If nothing matches and there is no ..., the program terminates.
Memory trick: catch like a funnel — narrow at the top, wide at the bottom.
7.7 Theory

Standard exception classes

C++ already has exception classes in <stdexcept>. They store a message. You read it with e.what().

ClassMeaning (beginner)Typical use
runtime_errorSomething went wrong while runningGeneral failure message
invalid_argumentA function got a bad valueNegative number, empty text
out_of_rangeIndex / position is outside limitsArray index 9 when size is 3
overflow_errorNumber became too bigRare in first-year labs

Need #include <stdexcept>. Catch by reference: catch (runtime_error& e).

7.7 Example · runtime_error

Standard exception: runtime_error

#include <iostream>
#include <stdexcept>
using namespace std;

int main() {
    int age = -5;
    try {
        if (age < 0)
            throw runtime_error("Age cannot be negative");
        cout << "Age = " << age << endl;
    }
    catch (runtime_error& e) {
        cout << e.what() << endl;
    }
    return 0;
}
Age cannot be negative

e.what() returns the message you put inside runtime_error("...").

7.7 Example · invalid_argument

Standard exception: invalid_argument

#include <iostream>
#include <stdexcept>
using namespace std;

int main() {
    double number = -9;
    try {
        if (number < 0)
            throw invalid_argument("Cannot take square root of a negative");
        cout << "Number is OK" << endl;
    }
    catch (invalid_argument& e) {
        cout << e.what() << endl;
    }
    return 0;
}
Cannot take square root of a negative

Use this when the input value itself is not allowed.

7.7 Example · out_of_range

Standard exception: out_of_range

#include <iostream>
#include <stdexcept>
using namespace std;

int main() {
    int marks[3] = {40, 55, 70};
    int index = 5;
    try {
        if (index < 0 || index >= 3)
            throw out_of_range("Index is outside the array");
        cout << "Mark = " << marks[index] << endl;
    }
    catch (out_of_range& e) {
        cout << e.what() << endl;
    }
    return 0;
}
Index is outside the array

Always check the index before you read marks[index].

7.7 User-defined type

Throwing your own class — complete program

Simple meaning: Make a small class that describes the error, then throw an object of that class.
#include <iostream>
#include <string>
using namespace std;

class NegativeAge {
public:
    string message;
    NegativeAge(string m) { message = m; }
};

int main() {
    int age = -5;
    try {
        if (age < 0)
            throw NegativeAge("Age cannot be negative");
        cout << "Age = " << age << endl;
    }
    catch (NegativeAge e) {
        cout << e.message << endl;
    }
    return 0;
}
Age cannot be negative
7.7 Complete program

Two user-defined exception classes

#include <iostream>
#include <string>
using namespace std;

class NegativeAge {
public:
    string message;
    NegativeAge(string m) { message = m; }
};
class FailMark {
public:
    int mark;
    FailMark(int m) { mark = m; }
};

int main() {
    int age = 20, mark = 25;
    try {
        if (age < 0) throw NegativeAge("Age cannot be negative");
        if (mark < 40) throw FailMark(mark);
        cout << "Student is OK" << endl;
    }
    catch (NegativeAge e) { cout << e.message << endl; }
    catch (FailMark e) { cout << "Fail mark: " << e.mark << endl; }
    return 0;
}
Fail mark: 25

Each class is a different type, so each needs its own catch.

7.7 Complete program

Nested try / catch (inner then outer)

#include <iostream>
using namespace std;

int main() {
    try {
        try {
            throw 10;
        }
        catch (int n) {
            cout << "Inner catch: " << n << endl;
            throw;   // rethrow the same exception
        }
    }
    catch (int n) {
        cout << "Outer catch: " << n << endl;
    }
    return 0;
}
Inner catch: 10
Outer catch: 10

throw; with nothing after it means: “pass the same error to the next catch outside.”

Practical 4

#include <iostream>

Exam tips

Common beginner mistakes

  • Writing MyMath.add() like Java — in C++ it is MyMath::add() for namespaces.
  • Forgetting template <typename T> above the function or class.
  • Creating Box marks; — must be Box<int> marks;.
  • Throwing an int but catching a string — types must match.
  • Mixing throw "hi" with catch (string s) — that throw is const char*.
  • Putting code after throw inside the same try and expecting it to run — it will not.
  • Placing catch (...) first — it steals every exception.
  • Forgetting #include <string> or <stdexcept>.
